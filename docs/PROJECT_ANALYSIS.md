## Общее состояние

Проект — модульный монолит на Java 21 и Spring Boot 3.4.0, разделённый на 14 пакетов. Основные сценарии: регистрация, JWT/TOTP, кошелёк, одиночные ставки, расчёт результатов, лимиты, бонусы и заявки на вывод. Антифрод включает правила, сигналы, оценку риска и связи аккаунтов.

Сильные стороны: разделение по предметным областям, BigDecimal, транзакции и optimistic locking кошелька, ledger с ключами идемпотентности, расширяемый FraudRule и сохранение объясняющих риск сигналов.

Обязателен JWT_SECRET — Base64-ключ минимум из 32 случайных байт. Wrapper, Dockerfile и Compose-файл отсутствуют.

## Проверки

До исправлений инкрементальный `mvn test` завершался с **36 тестами и 30 ошибками** загрузки контекста. В Git находился changelog из `target/classes` с включениями только до `011`; исходник включал миграции до `015`.

Чистая сборка выявила неверные XSD-адреса и TEXT/CLOB в H2. Регрессионные тесты до исправлений воспроизвели доступ с MFA-токеном, отсутствие повторной проверки блокировки и сбой вывода из-за отсутствующего ID.

Итоговая чистая сборка выполняет **56 тестов**, включая 20 добавленных сценариев в [SecurityRegressionTests](../src/test/java/com/example/sportsbook/security/SecurityRegressionTests.java) и [WithdrawalIntegrationTests](../src/test/java/com/example/sportsbook/payment/WithdrawalIntegrationTests.java). Старые проверки прямого списания обновлены под закрытие небезопасного endpoint.

Ограничение: интеграционные тесты используют H2 в PostgreSQL mode; Redis velocity проверяется Mockito. Реальные PostgreSQL, Redis и внешние платежи не запускались. SecurityIntegrationTests отдельно отключает Liquibase и использует create-drop; остальные контексты с Liquibase проверяют миграции на H2.

## Оставшиеся ограничения

- RegistrationVelocityRule существует, но UserService.register пока не вызывает FraudEngine и не передаёт IP.
- Завершение внешнего вывода и снятие удержания не реализованы. Повторный POST заявки не имеет клиентского ключа идемпотентности.
- Outbox сохраняет события, но обработчик только логирует и меняет статус; публикации в брокер нет.
- Exposure Prometheus настроен, но micrometer-registry-prometheus отсутствует.
- OpenAPI / Swagger и реальные Testcontainers-проверки отсутствуют.
- Спецификация описывает целевой объём, который шире кода; исторические статусы итераций не подтверждают выполнение всех требований.
